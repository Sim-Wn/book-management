## 面试可能追问的点（先想好自己的答案）

1. **为什么下单要在服务端重新算钱？** 前端传来的价格不可信，用户可以直接改请求体；服务端按 `book_id` 查库并锁定行，才能防篡改和超卖。
2. **怎么防超卖？** 事务里 `SELECT ... FOR UPDATE` 锁住图书行，校验库存后再扣减；库存不足直接回滚。
3. **JWT 存在 localStorage 有什么风险？** XSS 可以读取；更稳妥的是 HttpOnly Cookie + CSRF 防护。当前项目是课程 / 演示规模，做了 token 校验与 401 处理，生产会更进一步。
4. **为什么销量在「订单完成」才加？** 下单不等于成交，中途可能取消或退货；把销量与「已完成」绑定，统计口径才稳定。
5. **换书为什么要双方确认？** 交换是不可逆操作，单方确认容易产生纠纷；两人都点同意后再互换归属，并用行锁避免并发重复完成。
6. **图片为什么后端还要处理一遍？** 前端裁剪只解决显示比例，原图可能几 MB；Sharp 统一压缩成 JPEG 能控制体积，也顺手过滤掉伪造扩展名的文件。
7. **有没有做测试？** 有。Vitest + Supertest 直接挂载 Express app 做集成测试，另有 60 项冒烟脚本跑完整业务流；CI 在 MySQL 容器里自动执行。下一步会补前端组件测试与端到端测试。
